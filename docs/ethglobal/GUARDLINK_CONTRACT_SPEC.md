# GuardLink Arc integration specification

Build and test NEW production-quality demo contracts in Arc Studio. This extends an inherited cooperative insurance prototype, not a from-scratch product. Target Arc Testnet (chain 5042002), canonical ERC20 USDC 0x3600000000000000000000000000000000000000 (6 decimals). Gas and ERC20 USDC share one underlying balance; do not double-count.

Implement a GuardLinkPool contract and nontransferable ERC721 policy records using OpenZeppelin. One pool is one cooperative. Member eligibility and initial governance/jury rosters are explicitly bootstrapped for a labelled demo; do not claim Sybil resistance or unbiased randomness. Bootstrap admin is 0xeb010023C8c20FA1E1A849373E36bf9B1f82DE11. Constructor must accept this admin, the token address and initial contribution/coverage/term parameters. Do not require any host private key. Record the actual deployment signer separately.

Required interface (keep these exact signatures for app integration):
- join() external; initial member verification by admin via verifyMember(address,bool); no self verification.
- contribute() external returns(uint256 policyId), transferFrom configured contribution, mint policy. public policies(uint256) returns(address member,uint64 start,uint64 end,uint128 limit,uint128 used). tokenURI must contain no medical or identity details. contributionAmount(), coverageLimit(), termDays(), nextPolicyId(), members(address), verifiedMembers(address), balanceOf(address) readable.
- submitClaim(bytes32 claimId,uint256 policyId,uint128 requestedAmount,uint64 incidentAt,bytes32 evidenceCommitment) external. claimant must own active eligible coverage, amount >0 within remaining coverage. Reserve policy exposure on submission to prevent parallel claims exceeding remaining limit. Validate incident falls within coverage and not in future; allow submission after expiry only for an incident in the covered interval within a clearly defined 30-day grace window. No raw titles, diagnoses or files on-chain.
- assignJury(bytes32 claimId,address[3] jurors) external admin. claimants, declared local contact, duplicate and unverified jurors excluded. A local contact can be recorded on claim before panel selection, and cannot veto or decide it. For hackathon bootstrap, roster assignment is centralized and explicitly documented. Once a ballot exists no panel replacement. Selection randomness is out of scope.
- vote(bytes32 claimId,bool approve,uint128 amount,bytes32 rationaleHash) external. one vote per selected juror. Two matching approval+amount ballots approve. Two rejection ballots reject. Three divergent votes stay unresolved. 72-hour deadline; zero/no quorum remains unresolved. All amounts canonical USDC units.
- settle(bytes32 claimId) external permissionless, payout ONLY to claimant wallet, only after approval and only once. Check-effects-interactions, reentrancy guard, SafeERC20. Insufficient funds must preserve approved status and be retriable; no partial payout. Payment and status event only after successful transfer. No admin arbitrary withdraw or AI payout power.
- appeal(bytes32 claimId) external claimant, rejected only, at most once. assignAppealJury(bytes32,address[3]) admin, three disjoint verified reviewers excluding claimant/contact. appealVote(bytes32,bool,uint128,bytes32) same matching rule; later settle works for approved appeal. Preserve coverage reservation through rejection until appeal/grace expiry; document release behavior.
- getClaim(bytes32) view return a flat struct with claimant, policyId, requestedAmount, approvedAmount, status, paid, appealed, deadline, contact and commitments, and getJury(bytes32,bool appeal) returns three addresses. Define readable numeric enum and include ABI in output.
- proposeRules(uint128 contribution,uint128 limit,uint32 termDays,string description) external verified member returns(uint256). snapshot eligible members so later verification changes cannot change eligibility for that proposal. voteProposal(uint256,bool) once per snapshotted verified member; 50% quorum rounded up, 2/3 support rounded up, 72h voting and execution only after deadline. executeProposal(uint256) permissionless when passed, prospective only. Proposal getters and events for UI. No unbounded member loops during execution. For treasury, implement same governed proposal process for explicit, limited purposes that cannot bypass claim authorization or spend committed payout funds; if a safe general treasury transfer cannot be delivered, return a clear unsupported capability rather than owner withdrawal.

Emit join/verify/contribution/policy/claim/jury/ballot/approval/rejection/payout/appeal/proposal/vote/execution events with IDs and amounts. Use bytes32 IDs matching keccak256 of the API's UUID string. Public records are pseudonymous, not anonymous.

Tests MUST cover duplicate vote, unauthorized vote/admin, partial differing amounts, empty quorum, failed transfer, insufficient reserve then retry, double settlement, policy overcommit, expired/noncovered incidents, appeal independence and one appeal, governance snapshot and prospective terms, nontransferable NFT. Include mock ERC20 for local testing. Run tests, review, deploy to Arc Testnet if funded by Studio. If deploy unavailable deliver tested artifacts with honest status. No mainnet or paid upgrades. Return sources, ABIs, test results, deployment receipts and shareable Studio URL. Include any interface deviations explicitly. Do not expose secrets or alter public privacy requirements.
